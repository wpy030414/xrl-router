# xrl-router — 产品需求文档

> 版本: CalVer · 更新日期: 2026-08-25

## 1. 产品目标

| 目标 | 衡量方式 |
|------|---------|
| 统一接入 | 通过单一端点访问所有 Provider |
| 零摩擦启动 | 从打开应用到发出第一个请求 < 3 分钟 |
| 可靠运行 | 单个 Key 失效不影响服务 |
| 透明可观测 | 所有请求的 token 用量、延迟、成功率可追踪 |

## 2. 用户画像与场景

### 2.1 主要用户：AI 开发者

- 熟悉 API 调用，了解 REST/HTTP
- 每天使用，作为日常开发基础设施
- 核心诉求：一个端点接入所有模型，密钥自动管理，本地运行

### 2.2 次要用户：Claude Code / AI IDE 用户

- 会用终端，不一定了解 API 细节
- 核心诉求：让 Claude Code 能用非 Anthropic 的模型

### 2.3 核心使用场景

**场景 A：首次配置**
1. 打开 xrl-router 桌面应用
2. 在「供应商」页面添加 Provider（选类型、填 URL、填 Key）
3. 创建 Service Key
4. 在 Claude Code 配置 base URL 和 Service Key
5. 开始使用

**场景 B：密钥故障恢复**
1. Provider 返回 401 → Key 自动标红
2. 系统自动切换到下一个可用 Key
3. 后续请求透明继续

**场景 C：插件自动发现**
1. 启动 xrl-router-plugin-wukong
2. 插件 WS 连接到 Router → 发送注册信息
3. Router 弹出确认对话框
4. 用户确认 → 委托供应商自动激活

**场景 D：局域网设备快速接入**
1. 主机在「密钥管理」页创建密钥 → 弹窗显示分发链接
2. 设备浏览器打开链接 → 按平台显示一行命令
3. 设备复制命令到终端执行一次
4. 设备上的 Claude Code 直接通过主机网关使用所有模型

## 4. 协议转换规格

下游统一暴露 Anthropic Messages API、OpenAI Chat Completions API、OpenAI Responses API 三入口。所有客户端格式先经 IR（中间表示层）统一抽象，再渲染为目标上游格式。

### 4.1 必须支持的转换特性

- ✅ 文本消息
- ✅ 系统提示
- ✅ 工具调用
- ✅ 工具结果
- ✅ 思考过程
- ✅ 工具选择
- ✅ 流式响应
- ✅ 缓存 token
- ✅ OpenAI Responses API
- ✅ server-side web_search 工具归一化

### 4.2 usage 语义

| 项 | 规则 |
|----|------|
| 合并策略 | 真实值覆盖估算占位 |
| Responses input_tokens | 减去 cached_tokens，保持增量口径 |
| 上下文超限预警 | 仅 warn 日志，不阻断请求 |

### 4.3 流式与非流式

上游始终走流式（`ir_request.stream = true`）。客户端 `stream: false` 时，引擎收集全部 SSE 事件后返回完整 JSON 响应。

## 5. 密钥池规格

| 状态 | 颜色 | 触发条件 | 行为 |
|------|------|---------|------|
| 正常 | 🟢 绿 | 初始 / 请求成功 | 正常使用 |
| 低配额 | 🟡 黄 | 402 / 429 | 跳过，冷却 300 秒后自动恢复 |
| 失效 | 🔴 红 | 401 / 403 | 永久跳过 |

## 6. Token 配额规格

每个 Service Key 可配置 5 小时和 7 天两个滚动窗口的 token 上限。

| 项 | 规则 |
|----|------|
| 窗口定义 | 滚动窗口，按 Unix 时间对齐 |
| 用量口径 | prompt + completion + cache_read_input_tokens |
| 超限判定 | used >= limit 即 429 |
| 恢复方式 | 窗口滚动重置后自动恢复 |
| 错误响应 | 429 + retry-after 头 + quota_error 错误体 |

## 7. 故障转移规格

同一模型别名配置在多个 Provider 上时，网关按序尝试全部候选，上游故障自动切换。

| 项 | 规则 |
|----|------|
| 开关 | 设置页「路由」Tab（默认关闭） |
| 触发切换 | 上游 5xx / 网络错误 / 响应头超时 |
| 冷却 | 失败 provider 冷却 60s |
| 最终错误码 | 全部候选失败：502 / 504 / 透传上游错误 / 503 |

## 9. 局域网分发规格

把本机网关能力延伸到局域网设备。

| 项 | 规则 |
|----|------|
| 单 listener + IP 限制 | `/api/*` 管理端点仅 loopback；`/v1/*` 对外开放 |
| 分发链接 | `http://<本机IP>:19068/install?t=<明文key>` |
| 消费端选择 | Claude Code + ChatGPT/Codex |
| 安全边界 | 密钥明文嵌入 URL，仅限可信设备 |

## 10. 本地模型规格

在本机下载并运行 GGUF 模型，自动注册为网关内 Provider，对外暴露方式与云端 Provider 一致。

### 10.1 模型获取

| 项 | 规则 |
|----|------|
| 来源 | HuggingFace Hub（搜索 + 仓库详情 + 文件下载） |
| 格式 | 仅 GGUF |
| 镜像 | 可切换 HF Mirror（settings 持久化） |
| 存储 | `app_data_dir/models/{id}/model.gguf` |
| 下载中断 | 支持取消，`.part` 临时文件自动清理 |

### 10.2 引擎生命周期

| 项 | 规则 |
|----|------|
| 引擎 | llama-server（自动下载对应平台二进制） |
| GPU 后端 | Metal / CUDA / Vulkan / ROCm / CPU（自动检测 + 手动选择） |
| 启动序列 | 首选后端 → CPU 兜底 |
| 健康检查 | 启动后 120s 内等待 `/health` 返回 200 |
| 端口 | 自动分配空闲端口 |
| 崩溃重启 | 5s / 15s / 45s 退避，最多 3 次 |
| 自启动 | `autostart=1` 的模型在应用启动时自动拉起 |

### 10.3 注册为 Provider

| 项 | 规则 |
|----|------|
| Provider ID | `local-{model_id}` |
| Provider Kind | Chat Completions |
| Base URL | `http://127.0.0.1:{port}` |
| API Key | 随机 32 hex，AES 加密入库 + 同步进 KeyPool |
| Model | `display_name` = 用户命名，`tier` = `local` |

## 13. 风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 上游 API 格式变更 | 中 | 版本锁定 + 兼容性测试 |
| SQLite 高并发瓶颈 | 低 | WAL 模式 + 异步批量写入 |
| 协议转换丢失特性 | 中 | 不兼容特性显式报错 |
| 上游挂起网关卡死 | 低 | 独立超时保护 |
| 密钥泄露 | 低 | AES-256-GCM + Argon2 |
